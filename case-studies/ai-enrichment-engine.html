AI Live Postman

AI-Powered Enrichment Engine

Replacing 2.5 hours of daily manual research with a Clay-based workflow that surfaces real-time buying signals — so reps spend time selling, not searching.

The Problem

Reps were spending 2–3 hours a day on research. That's a rep tax no one was measuring.

When I audited how Postman's outbound reps were spending their time, the answer was uncomfortable: a significant chunk of every workday was pure manual research — pulling from ZoomInfo, cross-referencing LinkedIn, checking company websites for news, manually updating Salesforce fields. None of it was selling.

The data problem was equally bad. Salesforce records for target accounts were incomplete — missing job titles, wrong contact info, no tech stack signals, no indication of whether a company was in a buying cycle. Reps were effectively sending generic outreach because they lacked the context to personalize.

The core issue wasn't effort — it was infrastructure. Reps were working hard but fighting the data layer constantly. The solution wasn't to hire more SDRs. It was to build a system that eliminated the research burden entirely.
  • No unified signal layer: intent data, firmographics, and contact data lived in separate tools with no aggregation
  • Static enrichment: records were enriched once at creation and never updated — stale data within 90 days
  • No prioritization logic: reps worked accounts in alphabetical order, not by likelihood to convert
  • Manual CRM hygiene: reps responsible for updating their own records, which meant it rarely happened

The Approach

Evaluate build vs. buy. Pick the right abstraction layer. Design for rep adoption, not just technical elegance.

I evaluated three approaches before landing on Clay as the core platform:

Option: Custom Python scripts
✗ High engineering dependency
✗ Hard to maintain as data sources change
✓ Maximum flexibility
Option: Extend ZoomInfo workflow
✗ Single-source enrichment only
✗ No signal aggregation capability
✓ Already in stack

Clay won for three reasons: API-first design that lets you pull from 75+ data sources in a single table, no-code accessibility so RevOps can own it without engineering, and built-in AI enrichment using Claude/GPT to generate personalized insights at scale. It was the right abstraction layer — powerful enough for complex logic, operable without a dedicated engineer.

The design principle I kept returning to: the output has to be so obviously useful that reps pull it up before every call. If the data doesn't directly inform the outreach message, it won't get used. Every enrichment field we built had to answer: "would a rep change their email or call script based on this?"

The Build

A multi-source enrichment waterfall with an AI scoring layer — all syncing back to Salesforce automatically.

01
Data Ingestion — Pull target accounts from Salesforce
Clay table connected to Salesforce via API. New leads and target accounts flow in automatically based on lifecycle stage triggers. No manual imports.
02
Enrichment Waterfall — Company and contact data
Multi-source waterfall: ZoomInfo for firmographics → Clearbit for tech stack → LinkedIn for contact info and seniority → web scraping for recent news. Each source fills gaps left by the last.
03
Signal Layer — Buying intent and trigger detection
Automated signals pulled in real-time: G2 category review activity, recent funding events, active job postings in technical roles (growth signal), and technology change detection (switching signal).
04
AI Scoring — Claude synthesizes signals into a prioritization score
Claude reads the full enrichment context and returns a scored assessment: ICP fit rating (1–5), trigger strength, and a one-sentence "why reach out now" summary written in plain English for the rep.
05
Salesforce Sync — Push enriched fields and scores back
Enriched fields, AI score, and trigger summary written back to Salesforce automatically. Custom field on the lead/contact record surfaces the "why now" summary directly in the rep's workflow.
06
Sequence Trigger — Auto-enroll high-scoring prospects in Outreach
Prospects scoring above threshold are enrolled in the appropriate Outreach sequence automatically. Below-threshold records are flagged for human review rather than silently dropped.

Key Takeaways

What I'd tell anyone building this.

💡 Rep adoption is the only metric that matters at launch. The most technically sophisticated enrichment system fails if reps don't trust the data. Start with one or two high-signal fields and prove accuracy before expanding. Trust is earned record by record.
🔁 Waterfalls beat single-source enrichment every time. No single provider has 100% coverage. Building the logic to try source A, fall back to B, then C is annoying to set up but results in dramatically higher completion rates.
🤖 LLMs are best used for synthesis, not raw data retrieval. Don't ask Claude to find a company's revenue — ask it to read 10 signals and write a one-sentence "why now" that a rep could copy into an email. That's where AI adds unique value.
⚠️ Build the human-review path before you build the automation. High-scoring auto-enrollments are great. But you need a clear process for the 30% that score below threshold — otherwise they fall into a void and no one notices.
